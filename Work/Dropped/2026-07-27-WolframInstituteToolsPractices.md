## Spec

Origin: "there are some good practices in https://github.com/WolframInstitute/WolframInstituteTools we should clone and apply."

`WolframInstitute/WolframInstituteTools` is private; the `p135246` account has access and `gh repo clone` works.
A shallow clone shows two things worth taking, one convention to decide on, and a set of tools that solve problems this repo has already hit.

The biggest gap it exposes is documentation.
MathNotebook exports thirteen symbols whose entire documentation is a `::usage` string; WolframInstituteTools carries a real `Documentation/English/` tree — a `ReferencePages/Symbols/<Symbol>.nb` per exported symbol, plus `Guides/` and `Tutorials/` — with the built index committed under `build/`, so F1 and the Documentation Center work on an installed paclet.
That is what a published paclet should look like, and this repo's `PacletInfo.wl` has no Documentation extension at all.

The tools are the other half. `checkNotebooksCloudDependencies` addresses precisely the failure this project already worked around by hand: a notebook deployed to the cloud whose stylesheet reference does not resolve there. `convertNotebookToMarkdown` / `convertMarkdownToNotebook` bear directly on how the tutorial is authored and on `LaTeXPaperImport`. `buildTestsFromNotebook` allows tests to be written in a notebook rather than by hand in `.wlt`. `codeInspector` gives a formatting and lint standard to hold code to.

Done when the exported symbols have real documentation pages that build, the applicable tools are in use rather than admired, and the conventions this repo chose *not* to adopt are recorded with a reason.

### Requirements

- **Read the repo properly first** and write down what applies. This spec is based on a file listing and doc-page names, not on the source — the findings task supersedes it where they disagree.
- **Documentation tree** for the thirteen exported symbols: `MathNotebook/Documentation/English/ReferencePages/Symbols/<Symbol>.nb`, a Guide page listing them by group, and the existing tutorial content as a proper `Tutorials/` page rather than an `Assets/` notebook. Add the Documentation extension to `PacletInfo.wl`. Verify F1 works on an installed build.
- **Docs build** reproducible from a script under `Scripts/`, in keeping with the rule that every `.nb` artifact is generated, never hand-edited.
- **`checkNotebooksCloudDependencies`** run over everything `Scripts/DeployPreviews.wls` publishes, so a preview that cannot render in the cloud is caught before it is linked from the README.
- **`LICENSE`** at the repo root — `PacletInfo.wl` claims MIT and there is no license file.
- **Layout is settled:** this repo keeps `MathNotebook/` at the root. WolframInstituteTools nests its paclet as `Paclet/<Name>/`; that is inspiration, not a template, and is not to be adopted (see Decisions).

### Edge cases & out of scope

- The repo is private, so nothing may be copied into this public-facing paclet without deciding what is a *practice* (free to adopt) and what is *their code* (needs permission or a dependency). Prefer depending on the paclet over vendoring its source.
- A dependency on a private paclet cannot be a load-time requirement of a published paclet — build-time and dev-time use only.
- Documentation pages are notebooks; committing built docs adds weight to the archive. Check what that does to the paclet size before adopting `build/` wholesale.
- Out of scope: their LLM prompt and blog tooling, which has nothing to do with writing papers.

## Dropped — 2026-07-27, with one requirement carried forward

- **Prompt:** "we should probably reduce, and concentrate on doing what is needed to have a working paclet."
- **Carried to `Release`:** the **`LICENSE` file**. `PacletInfo.wl` declares `"License" -> "MIT"` and the repo root has no such file — the only defect in this item that is legal rather than technical, and the only one that touches a *published* paclet. It is now a requirement and part of T1 of `First Public Release`. The copyright line is left to Pavel to state: `"Creator"` is `Pavel Hajek` and `"PublisherID"` is `WolframInstitute`, and which of those owns the copyright is not something to guess.
- **Why the rest goes:** the bulk of the item is a documentation tree — a `ReferencePages/Symbols/<Symbol>.nb` for each of the **23** symbols `PacletInfo.wl` exports, plus Guide and Tutorial pages, a build script, and the Documentation extension. That is a large, mostly mechanical effort whose payoff is F1 working in the Documentation Center, on a research paclet whose users are Pavel and whoever he hands it to, and which already ships a nine-section tutorial notebook and a usage string per symbol. The cost is real and the marginal reader is hypothetical.
- **`checkNotebooksCloudDependencies`** was the other tempting piece — it catches a deployed notebook whose stylesheet does not resolve in the cloud, which this project *has* hit by hand. But it lives in a **private** repo, and a published paclet cannot depend on one; adopting it means vendoring code with permission, which is a conversation, not a task.
- **Reopen if:** the paclet is ever submitted to the Wolfram Paclet Repository, which does require real documentation pages, or if someone other than Pavel starts using the API.
